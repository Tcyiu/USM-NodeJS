# Лабораторная работа № 4 — CRUD-приложение с PostgreSQL и Sequelize

Продолжение проекта из лабораторной работы № 3: веб-приложение для управления учебными курсами и преподавателями на Node.js, Express, EJS и PostgreSQL. Основные данные сохраняются в PostgreSQL, а модели и запросы организованы по MVC.

**Репозиторий:** [Tcyiu/USM-NodeJS — папка lab4_egor_fomin](https://github.com/Tcyiu/USM-NodeJS/tree/master/lab4_egor_fomin)

## Реализовано

- Подключение к PostgreSQL с параметрами из `.env`; пароль не хранится в исходниках.
- Модели Sequelize `Teacher` и `Course`, связь один-ко-многим через `teacherId`.
- CRUD-просмотр, добавление, редактирование и удаление курсов и преподавателей.
- Получение преподавателя и его курсов через ассоциации Sequelize.
- Выбор преподавателя из списка при создании/редактировании курса.
- Удаление преподавателя с курсами блокируется и защищено ограничением внешнего ключа.
- Поиск курса по названию и фильтрация по преподавателю/семестру, включая комбинацию всех условий; условия применяются в PostgreSQL запросе.
- Серверная и модельная валидация полей, формата и уникальности email, кредитов, семестра и преподавателя.
- Страница статистики с общими количествами, разбиением по семестрам, курсами преподавателей и лидером по числу курсов.
- Навигация, логирование запросов, страницы 404/500 и централизованная обработка асинхронных ошибок.
- Автоматические таблицы создаются при запуске через `sequelize.sync()` без удаления существующих данных.

## Требования

- Node.js 18.11 или новее и npm.
- PostgreSQL, запущенный локально или доступный по сети.
- Созданная в PostgreSQL база данных `node_courses`.

## Установка и запуск

```powershell
cd lab4_egor_fomin
npm install
npm start
```

При успешном соединении выводится `Database connection established`, затем создаются отсутствующие таблицы `Teachers` и `Courses`, и сервер запускается на <http://localhost:3000>. Другой порт можно задать через `PORT`. Режим разработки с автоматическим перезапуском:

```powershell
npm run dev
```

Если база недоступна или параметры подключения неверны, сообщение об ошибке выводится в терминал. Убедитесь, что PostgreSQL запущен, база уже создана, а `.env` содержит корректные значения.

## Маршруты

| Метод | URL | Назначение |
|---|---|---|
| GET | `/` | Перенаправление на `/courses` |
| GET | `/courses` | Список, поиск и фильтрация курсов |
| GET | `/courses/new` | Форма создания курса |
| POST | `/courses` | Сохранение курса |
| GET | `/courses/:id` | Просмотр курса и сведений о преподавателе |
| GET | `/courses/:id/edit` | Форма изменения курса |
| POST | `/courses/:id/edit` | Сохранение изменений курса |
| POST | `/courses/:id/delete` | Удаление курса с подтверждением в браузере |
| GET | `/teachers` | Список преподавателей и число их курсов |
| GET | `/teachers/new` | Форма создания преподавателя |
| POST | `/teachers` | Сохранение преподавателя |
| GET | `/teachers/:id` | Преподаватель и его курсы |
| GET | `/teachers/:id/edit` | Форма изменения преподавателя |
| POST | `/teachers/:id/edit` | Сохранение изменений преподавателя |
| POST | `/teachers/:id/delete` | Удаление преподавателя без курсов |
| GET | `/statistics` | Статистика по данным PostgreSQL |

Пример комбинированного фильтра: `/courses?search=node&teacherId=2&semester=1`.

## Проверка

Запустить автоматические тесты проверки валидации:

```powershell
npm test
```

Также проверьте приложение в браузере:

1. Создайте преподавателя; проверьте, что повторный email не сохраняется.
2. Создайте для него курс; проверьте страницу `/teachers`, подробности курса и преподавателя.
3. На `/courses` проверьте поиск по названию, каждый фильтр отдельно и комбинацию `search`, `teacherId`, `semester`.
4. Отредактируйте и удалите курс; подтвердите окно удаления.
5. Попробуйте удалить преподавателя с курсами: удаление должно быть запрещено; преподавателя без курсов можно удалить.
6. Проверьте `/statistics`, пустые поля/некорректный email, кредит `0`, семестр `9`, несуществующие ID и неизвестный URL.
7. Перезапустите сервер: созданные записи должны остаться в PostgreSQL.
