# Лабораторная работа № 5 — аутентификация и защита приложения

Продолжение проекта из лабораторной работы № 4: система управления учебными курсами и преподавателями на Node.js, Express, EJS, PostgreSQL и Sequelize.

**Репозиторий:** [Tcyiu/USM-NodeJS — папка lab5_egor_fomin](https://github.com/Tcyiu/USM-NodeJS/tree/master/lab5_egor_fomin)

## Реализовано

- Регистрация и вход с bcrypt-хешированием пароля; роль новых аккаунтов всегда `user`.
- Сессии с `httpOnly`, `sameSite=lax` cookie, сроком действия 1 час и обновлением сессии после входа.
- Выход только через `POST /logout`; профиль показывает роль, дату регистрации и последний вход, но не пароль/hash.
- Разграничение `user`/`admin`: чтение курсов и преподавателей доступно всем, статистика и профиль — авторизованным, изменение данных — администраторам. Проверки доступа стоят на серверных маршрутах, интерфейсные кнопки также скрываются.
- Валидация полей регистрации, входа, преподавателей и курсов через express-validator и дополнительная проверка бизнес-правил.
- Централизованный обработчик ошибок, страницы 403/404 и сообщения без SQL, stack trace или содержимого `.env`.
- Morgan выводит запросы в терминал и пишет дату, метод, URL, код ответа и время в `logs/requests.log`.
- Журналирует администраторские операции создания, изменения и удаления курса/преподавателя.
- Socket.IO отправляет событие `courseCreated` всем подключённым клиентам после успешного создания курса.
- Сохранены существующие CRUD, поиск, фильтры и статистика из lab4.

## Требования

- Node.js 18.11+ и npm.
- PostgreSQL; база данных `node_courses` должна быть создана заранее.

## Установка и запуск

В PowerShell из каталога проекта:

```powershell
npm install
```

Затем запустите:

```powershell
npm start
```

Приложение доступно на <http://localhost:3000>. Порт можно переопределить переменной `PORT`. Для разработки с перезапуском:

```powershell
npm run dev
```

Если при запуске появляется сообщение, что порт уже занят (`EADDRINUSE`), другой экземпляр приложения уже использует этот порт. Остановите его в его PowerShell-окне сочетанием `Ctrl+C`, затем повторите `npm start`. Если нужно запустить два экземпляра одновременно, укажите, например, `PORT=3001` в `.env` (или временно задайте `$env:PORT=3001` в PowerShell).

При запуске проверяется подключение к PostgreSQL, после чего Sequelize создаёт недостающие таблицы. Используется стандартное хранилище сессий Express в памяти: оно предназначено для лабораторной/локальной демонстрации; для production нужен внешний session store.

## Первоначальная настройка администратора

1. Зарегистрируйте аккаунт через `/register`.
2. Откройте psql или SQL-консоль PostgreSQL для базы `node_courses` и назначьте роль:

   ```sql
   UPDATE "Users" SET role = 'admin' WHERE email = 'admin@example.com';
   ```

3. Выйдите и выполните вход заново. Роль попадает в сессию во время входа.

Не добавляйте поле `role` в публичную форму регистрации: сервер назначает всем новым пользователям `user`.

## Маршруты

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET | `/register` | Все | Форма регистрации |
| POST | `/register` | Все | Создать пользователя |
| GET | `/login` | Все | Форма входа |
| POST | `/login` | Все | Проверить пароль и начать сессию |
| POST | `/logout` | Пользователь | Завершить сессию |
| GET | `/profile` | Пользователь | Профиль без пароля/hash |
| GET | `/courses` | Все | Список, поиск и фильтрация |
| GET | `/courses/:id` | Все | Подробности курса |
| GET/POST | `/courses/new`, `/courses` | Admin | Создать курс |
| GET/POST | `/courses/:id/edit` | Admin | Изменить курс |
| POST | `/courses/:id/delete` | Admin | Удалить курс |
| GET | `/teachers` и `/teachers/:id` | Все | Список и подробности преподавателей |
| GET/POST | `/teachers/new`, `/teachers` | Admin | Создать преподавателя |
| GET/POST | `/teachers/:id/edit` | Admin | Изменить преподавателя |
| POST | `/teachers/:id/delete` | Admin | Удалить преподавателя без курсов |
| GET | `/statistics` | Пользователь | Статистика |

## Проверка

Автоматические тесты:

```powershell
npm test
```

Ручная проверка ролей и защиты:

1. Зарегистрируйте обычного пользователя и войдите: откройте `/profile`, проверьте, что пароль и его hash нигде не отображаются.
2. Как гость откройте `/profile`: приложение перенаправит на `/login`.
3. Как `user` откройте `/statistics`: страница доступна. Откройте `/courses/new` или попробуйте отправить POST на создание: сервер вернёт 403, даже если запрос сформирован вручную.
4. Как администратор создайте курс/преподавателя, затем отредактируйте или удалите; соответствующие действия появятся в журнале терминала.
5. Проверьте пустые поля, ошибочный email, короткий пароль, несовпадение паролей, ошибочные кредиты/семестр и несуществующий `teacherId`.
6. Проверьте неверный пароль, повторную регистрацию email, страницу `/profile` после выхода и неизвестный URL (404).
7. Войдите администратором в двух окнах браузера. Создайте курс в одном: во втором появится уведомление без перезагрузки.
8. После запросов проверьте `logs/requests.log`. В таблице `"Users"` пароль должен выглядеть как bcrypt-хеш, например строка, начинающаяся с `$2`.

## Файлы и роли компонентов

- `models/User.js` — пользователь, уникальный email и роли.
- `controllers/authController.js`, `routes/authRoutes.js` — регистрация, вход, выход и профиль.
- `middleware/auth.js` — `isAuthenticated` и `isAdmin`.
- `middleware/validation.js` — express-validator проверки форм.
- `middleware/notFound.js`, `middleware/errorHandler.js` — 404 и централизованные ошибки.
- `middleware/logger.js` — Morgan для терминала; файл журнала настраивается в `app.js`.
- `app.js` — express-session, HTTP-сервер, Socket.IO и middleware приложения.
- `public/js/notifications.js` — отображение уведомлений `courseCreated`.

`.env` и `logs/requests.log` не должны загружаться в репозиторий; `.env.example` содержит только шаблон настроек.
